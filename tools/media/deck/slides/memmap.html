Safety built in

RDT only touches memory it knows is safe

Memory map

Access outside the ELF sections and your listed ranges is refused before anything is sent. Register blocks are read alone, at their exact size. Code and constants are read-only.

ELF check

On connect, RDT compares a sample of flash with each ELF. On a mismatch, every read and write to that MCU is refused, so a stale ELF never hits the wrong address.

RDT user manual · Part 1: Before you start

Two safety nets protect the device. The memory map: RDT refuses any access outside each MCU’s ELF sections and the ranges you list, before anything is sent. Register blocks are marked as peripherals and always read alone at their exact size, and code and constants are read-only. And the ELF check: on connect, RDT compares a sample of the flash on the device with each ELF. If they don’t match, every read and write to that MCU is refused, so a stale ELF can never read or write the wrong address.
